# U9 화면 전환 흐름도

> 2026-11-16 · 초안. 자동 전환이 충돌할 때의 규칙은 Sonnet max 검토로 위임 결정한다 `[U-결정 5]`.
> 전환은 두 종류다. **사용자 입력**과 **시스템 상태**(LoadComplete, CatchUpDone, Unlocked, RoomBought, Background/Foreground)다.

## 흐름도

  칸·그릇 탭       상점 버튼        도감 버튼        사진 버튼       앨범            설정
     ▼              ▼               ▼               ▼              ▼               ▼

     │  구하기       │                 │      │         │                              
     │               └─RoomBought─▶ P1(새 방)  ▼      ▼                               
     └─끌어 놓기 끝─▶ P1          P5 ──▶ P6z  P6z                                      

시스템: Unlocked (P1이 보이는 동안, 대기열) ──▶ Q2 ──닫기──▶ 원래 화면
시스템: Background 30분 이상 → Foreground ──▶ P0 (방치 계산) ──▶ P1

## Back 규칙 · UI 스택
- 화면은 스택이다. Back은 맨 위 하나를 닫는다.
- 우선순위는 U1을 따른다: 첫 안내 > 팝업 > 덮개 > 확대 > 전체 > P1 종료 확인.
- Full 화면은 스택에 쌓이고, P1로 가는 버튼(집 아이콘)은 두지 않는다. 깊이가 최대 3이라 Back이면 충분하다 (P1→P4→P5→P6z).

## 로딩 · 전환 중 입력
- P0과 화면 전환 애니메이션(0.2초) 동안에는 모든 입력을 무시한다 (K1 Busy).
- 장면 전환(Scene) 중에는 띠도 미룬다.

## 자동 전환 충돌 `[U-결정 5]`
결정은 **World(시스템)가 순서를 정하고, UI는 따르기만 한다.**

| 충돌 | 규칙 (초안) |
|---|---|
| Unlocked + 사용자가 버튼을 누르는 중 | 사용자 전환이 먼저다. 해금 팝업은 새 화면이 열린 뒤 대기열에서 나온다 (단, P8 사진 찍기 중에는 미룸) |
| Unlocked 여러 개 | U8 대기열: 시각 순서, 최대 연속 3개 |
| RoomBought + Unlocked | 방 넘김 연출 → 그다음 해금 팝업 |
| Foreground(30분 이상) + 팝업이 열려 있었음 | 팝업 상태를 버리고 P0으로. 확인 창(구매 등)은 '그만'으로 처리한다 (재화 변화 없음) |
| 첫 안내 중 Unlocked | 첫 정령 일러만 안내 단계로 보이고, 나머지는 안내가 끝난 뒤에 |

## U1~U8과 일치 확인
- 화면 ID, Back 부모, 팝업 대기열, 결과 코드 전환(방 구매)이 U1·U3·U6·U8과 같다.
