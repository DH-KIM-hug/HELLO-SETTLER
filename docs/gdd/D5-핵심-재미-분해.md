# D5 핵심 재미 분해

> 2026-11-16 사용자 결정: 핵심 재미는 **열어 보는 설렘**이다. 발견과 감상은 그 결과로 따라오는 보조 재미다.

## 핵심 재미 한 문장

**앱을 열 때마다 "내가 놓아 둔 것을 보고 누가 와 있을까?"가 궁금하고, 열자마자 그 답이 보인다.**

## 4관점 분해

| 관점 | 내용 |
|---|---|
| **입력** | 닫기 전에 놀잇감과 간식을 놓는다. 이것이 질문을 거는 행동이다. 열기는 앱 아이콘 탭 한 번이고, 답을 확인하는 행동이다 |
| **규칙** | 닫혀 있는 동안 일정 간격마다 놀잇감별로 방문을 판정한다. 판정 조건은 간식이 남았는지, 놀잇감 선호, 날씨, 계절, 시간대, 희귀도다. 결과는 열기 전까지 숨겨지고, 열 때 한꺼번에 정해져 보인다 |
| **결과** | 지금 놀고 있는 손님, 다녀간 손님의 선물, 처음 온 손님(도감 새 칸), 처음 본 모습(사진첩 새 칸), 간식이 얼마나 남았는지 |
| **피드백** | ① 열기: 첫 화면이 곧 집(마지막으로 본 방)이다. 로딩 뒤 1초 안에 손님이 보인다 ② 처음 온 손님: 반짝임, 짧은 소리, '새 손님!' 띠 ③ 희귀 손님: 다른 소리, 별 효과 ④ 선물: 놀잇감 옆 선물 아이콘을 탭하면 받는다 ⑤ 손님 탭: 짧은 한마디 말풍선 |

## 설렘을 만드는 시스템 관계

| 관계 | 설계 방향 |
|---|---|
| 방문 확률 ↔ 열기 간격 | 1~3시간 뒤 열면 거의 항상 누군가 와 있어야 한다 (빈 화면 = 설렘 실패). 수치는 X9와 T7에서 정한다 `[TBD]` |
| 희귀도 ↔ 기대 | 희귀 손님은 드물게, 하지만 "조건을 맞추면 언젠가 온다"는 믿음이 있어야 한다. 조건 힌트는 도감 빈 칸 실루엣으로 준다 |
| 날씨·계절 ↔ 다음에 열 이유 | 환경이 바뀌면 같은 배치에도 다른 손님이 온다. "비 오는 날에만 오는 아이"가 다시 들어올 이유가 된다 |
| 간식 소모 ↔ 돌봄 | 간식이 떨어지면 손님이 오지 않는다. 벌칙이 아니라 '다시 채우러 올 이유'로 쓴다 (D2: 잃는 것 없음) |
| 재화·상점 ↔ 질문 바꾸기 | 새 놀잇감과 간식을 사면 "이번엔 누가 올까"라는 새 질문이 생긴다. 재화는 질문을 넓히는 데만 쓰고, 효율 최적화에는 쓰지 않는다 |
| 친밀도 ↔ 장기 기대 | 자주 온 손님일수록 특별 모습과 선물이 열린다. 단골의 다음 단계도 설렘이 된다 |

## 핵심 기능 / 보조 기능

| 핵심 (열어 보는 설렘에 직접 필요) | 보조 (설렘을 키우지만 없어도 성립) |
|---|---|
| 놀잇감·간식 놓기 | 사진 찍기·사진첩 (감상 보조 재미) |
| 닫혀 있는 동안의 방문 판정과 방치 시간 계산 | 친밀도 단계와 특별 선물 |
| 열 때 결과 공개(첫 화면 = 집) | 꾸미기 테마 |
| 손님 캐릭터와 놀잇감별 모습 | 날씨·계절 (차별화 요소지만 MVP 최소 검증에는 시간대만으로도 가능) |
| 처음 온 손님 표시 + 도감 | 손님 한마디·프로필 |
| 선물 재화 + 상점(새 놀잇감·간식) | 광고 보상, 유료 재화, 클라우드 저장 |

## 재미 검증에 필요한 최소 기능

설렘이 생기는지 확인하는 가장 작은 판이다.
1. 집의 방 2개(첫 방 칸 5개, 상점으로 여는 두 번째 방 칸 4개). 방을 옆으로 넘겨 본다
2. 놀잇감 6종과 간식 2종 (기본 간식, 좋은 간식)
3. 손님 8명: 흔한 6명, 희귀 2명. 놀잇감마다 그림 1장씩
4. 방치 시간 방문 판정. 앱을 닫았다 열면 결과가 보인다
5. 처음 온 손님 표시와 도감 화면
6. 선물 재화와 아주 작은 상점 (놀잇감과 간식 몇 개)
7. 시간대(낮/밤)와 날씨(소수)를 조건으로 쓴다. 계절은 검증 판 이후에 넣는다 (D6 사용자 결정으로 날씨와 사진첩이 첫 판에 들어감)

**검증 질문:**
- 하루 동안 3번 이상 스스로 열어 보고 싶었는가?
- 열 때 빈 화면이 없었는가?
- 희귀 손님 조건을 맞추려고 배치를 바꿔 보았는가?
