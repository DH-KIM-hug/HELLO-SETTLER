## 공통 속성 (정적 ItemDef)

| 필드 | 타입 | 설명 |
|---|---|---|
| item_id | 문자열 | 고유. 이름과 다르다 |
| type | Toy/Food/Room/Currency/Keepsake | |
| name | 문자열 (한국어) | 화면 표시용 |
| description | 문자열 | 한 줄. 정령 쪽 말투. 숫자 금지 |
| icon_key | 문자열 | 그림 키 |
| max_stack | 정수 | 위 표 |
| price | 정수 또는 없음 | **상점 상품(ShopItemDef)이 소유한다.** ItemDef에는 두지 않는다 (G9) |

타입별 추가 필드(ToyDef의 pose_slots, FoodDef의 duration·attract 등)는 C5와 K7을 따른다.

## ID 규칙 (초안)
- 형식: `<타입접두어>_<영문소문자_밑줄>`. 접두어는 `toy_`, `food_`, `room_`, `cur_`, `keep_`이고, 정령은 `spirit_`, 장면은 `scene_`이다.
- 한 번 쓴 ID는 바꾸거나 다시 쓰지 않는다. 저장 파일이 ID로 기억하기 때문이다.
- 지운 아이템의 ID는 `deprecated` 목록에 남긴다. 저장 파일에서 만나면 건너뛰고 기록한다 (F4).

## 원본 vs 보유
- **원본 (정적):** ItemDef, ToyDef, FoodDef…
- **보유 (저장):** `inventory = {item_id: quantity}`. 보유 쪽에는 ItemId와 수량만 둔다. 놓인 놀잇감은 `placement[slot] = toy_id`이고, 소지품 수량에서 빼지 않고 '놓임'으로 계산한다.
  - 놓을 수 있는 수 = 보유 − 놓인 수 (파생).
- **소유자 원칙:**
  - 방문 확률은 SpiritDef와 K7 표가 갖는다. 놀잇감은 확률을 모른다.
  - 선물 내용은 GiftTableDef가 갖는다.
  - 가격은 ShopItemDef가 갖는다.

## 검증 규칙 (데이터를 읽을 때)
- **Error (시작 실패):**
  - item_id가 중복된다.
  - 다른 표가 없는 ID를 참조한다.
  - max_stack < 1이다.
  - 모든 SpiritDef.likes_toys에 들어 있는 놀잇감이 ToyDef에 없다.
- **Warning:**
  - 아무 정령도 좋아하지 않는 놀잇감이 있다 (쓸모없는 상품).
  - 처음 지급 놀잇감만으로 만날 수 있는 정령이 2명 미만이다 (첫날 설렘 부족).
