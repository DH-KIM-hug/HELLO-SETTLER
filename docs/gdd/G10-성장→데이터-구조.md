# G10 성장 → 데이터 구조

> 2026-11-16 · 초안. 저장 대상은 C5(사용자 확정)를 따르고, G단계에서 생긴 값을 더했다.

**중복 저장 없음:**
- 놀잇감 '놓임' 여부는 placement에만 저장한다. inventory에 따로 두지 않는다.
- 친밀도 단계는 visit_count에서 계산한다.
- 상품 '가짐' 표시는 inventory와 purchase_count에서 계산한다.

## 불러오기 순서
1. 저장 파일을 읽는다. 버전을 확인하고, 옛 버전이면 변환한다 (F4).
2. 정적 데이터를 읽고 검증한다 (G4 규칙).
3. 저장 데이터의 ID를 검사한다. 없는 ID는 deprecated 목록과 대조한 뒤 건너뛰고 기록한다.
4. 파생값을 다시 계산한다 (놓을 수 있는 수, bond_level, 잠김).
5. 방치 계산을 한다 (S5).
6. 화면에 그린다 (P1).

## 새 게임 초기값

| 값 | 초기값 (TEMP) |
|---|---|
| coins | 0 (첫 안내 끝에 +100) |
| inventory | toy_thimble_swing 1, toy_spool_slide 1 |
| rooms_owned | room_window |
| placement | 비어 있음. 첫 안내에서 그네를 놓게 한다 |
| food_bowls | room_window 그릇: 비어 있음. 첫 안내에서 기본 간식을 넣게 한다 |
| collection · pending_gifts · pity | 비어 있음 |
| visit_seq | 1 |
| save_seed | 무작위 64비트 |
| save_version | 1 |

## 저장 버전과 기본값
- 새 필드가 생기면 save_version을 +1 하고, 변환기에서 위 초기값으로 채운다.
- 필드가 빠져 있으면 초기값으로 채우고 경고를 기록한다.

## 검증 규칙
- 보유 수량은 0 ≤ qty ≤ max_stack이어야 한다. 범위를 벗어나면 잘라내고 경고한다.
- coins는 0 ≤ coins ≤ 최대여야 한다.
- placement의 toy가 inventory에 없으면 그 칸을 비우고 경고한다.
- visits_now의 정령이 두 칸에 있으면 한 칸만 남긴다.
- purchase_count > 구매 제한이면 제한값으로 둔다.

## 숫자 예제
- **상황:** 보유 놀잇감 4개. placement에 2개를 놓았다. coins 260.
- **불러온 뒤:**
  - 놓을 수 있는 놀잇감은 2개다.
  - 상품 shop_toy_ribbon(250)은 놀잇감 3개 이상이라 열린다. 살 수 있다.
  - shop_toy_button(400)은 놀잇감 4개 이상이라 열려 있지만, 재화가 부족해 살 수 없다.

## 저장 → 불러오기 동일성 테스트
- **Given** 위 상태에서 저장한다. **When** 불러온다. **Then** 다음이 같아야 한다.
  - 저장값이 모두 같다.
  - 파생값(놓을 수 있는 수, 잠김, 살 수 있는지)이 같다.
  - 방치 계산 결과가 같다 (같은 save_seed와 같은 경과 시간).
