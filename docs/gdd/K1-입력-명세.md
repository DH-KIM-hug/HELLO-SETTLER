# K1 입력 명세

> 2026-11-16 사용자 확정. 추가 결정: **끌어서 놓기도 넣는다** ("끌어서 놓기도 넣기"). 탭 두 번으로 놓는 방식도 그대로 둔다.
> **이 게임의 입력:** 캐릭터를 직접 움직이지 않는다. 휴대폰 터치(탭, 밀기, 집기)와 안드로이드 '뒤로'뿐이다. PC나 패드는 지원하지 않는다. 개발용 마우스는 탭으로 쓴다.

## 액션 목록

| 액션 | 기본 입력 | 방식 | 가능 조건 | 제한 |
|---|---|---|---|---|
| **TapSpirit** 정령 반응 | 정령 탭 | 뗄 때 판정 | 방 화면, 막는 팝업 없음 | 같은 정령은 반응이 끝날 때까지 다시 반응하지 않음 |
| **TapGift** 선물 받기 | 선물 표시 탭 | 뗄 때 판정 | 방 화면, 방치 계산 끝남 | 한 선물은 한 번만 받음 (C7) |
| **TapSlot** 칸 열기 | 칸(빈 칸 또는 놀잇감) 탭 | 뗄 때 판정 | 방 화면 | 정령이 노는 칸도 열 수 있음 (바꾸면 정령은 떠남, C7) |
| **TapBowl** 그릇 | 간식 그릇 탭 | 뗄 때 판정 | 방 화면 | 비었으면 바로 기본 간식으로 채움. 차 있으면 간식 고르기 판 |
| **SwipeRoom** 방 넘기기 | 좌우로 밀기 | 누름 → 이동 → 뗌 | 방 화면, 방 2개 이상 | 첫 방과 마지막 방에서 바깥쪽으로 밀면 살짝 튕기고 그대로 |
| **TapMenu** 아래 버튼 | 버튼 탭 | 뗄 때 판정 | 방 화면 | 첫 안내 중에는 안내된 버튼만 |
| **PickItem** 물건 고르기 | 고르기 판의 물건 탭 | 뗄 때 판정 | 고르기 판 열림 | 가진 물건만. 판을 연 칸에 놓는다 |
| **DragItem** 끌어서 놓기 | 고르기 판(또는 아래 '소지품' 판)의 물건을 누른 채 위로 끌기 → 칸 위에서 떼기 | 누름 → 이동 → 뗌 | 방 화면에서 판이 열려 있음 | 끌기 시작하면 판이 아래로 내려가 방이 보인다. 놓을 수 있는 칸이 빛나고, 손가락 아래 칸이 커진다. 칸 밖에서 떼면 취소(무변경). 놀잇감은 놀잇감 칸에만, 간식은 그릇 칸에만 놓인다. 화면 가장자리에 0.5초 머물면 옆 방으로 넘어간다 |
| **Buy** 사기 | 상품 탭 → 확인 창 '사기' | 뗄 때 판정 | 상점, 재화 충분 | 부족하면 '사기'가 흐림 (C7) |
| **Shutter** 사진 | 셔터 탭 | 뗄 때 판정 | 사진 찍기 덮개 | 찍는 중 0.5초 막음 (C7) |
| **ZoomArt** 일러 확대 | 두 손가락 집기 · 두 번 탭 · 끌어서 이동 | 연속 | 일러 크게 보기 | 1배~3배 |
| **Back** 뒤로 | 화면 위 '뒤로' 버튼 · 안드로이드 뒤로 | 뗄 때 / 시스템 | 방 화면 외 모든 화면 | 방 화면에서 뒤로 → "한 번 더 누르면 나가요" 띠, 2초 안에 다시 누르면 앱 종료 |
| **Dismiss** 닫기 | 판·팝업 바깥 탭 · 닫기 버튼 | 뗄 때 판정 | 고르기 판, 확인 창, 일러 해금 연출 | 첫 안내 말풍선은 바깥 탭으로 닫히지 않음 |

**놓는 방법은 두 가지다 (사용자 결정).**
- ① 칸 탭 → 고르기 판 → 물건 탭: 한 손으로 쉽고 정확하다.
- ② 판의 물건을 끌어 칸에 놓기: 여러 칸을 빨리 채우거나, 보면서 놓을 때 쓴다.

이미 놓인 놀잇감을 길게 눌러 다른 칸으로 옮기는 기능은 다음 판에서 다룬다 `[TBD]`. 길게 누르기가 탭이나 밀기와 겹치지 않는지 폰에서 먼저 시험해야 한다.

## 입력과 행동 분리
입력 처리는 '어떤 액션인지'만 판정해서 해당 시스템에 **요청**한다. 예를 들어 TapGift는 S8에게 '선물 받기' 요청만 보낸다. 실제로 줄지 말지는 S8이 다시 검증한다. 화면은 원본 데이터를 직접 바꾸지 않는다.

## 탭과 밀기 판정 (수치는 데이터 `Tuning.input`)

| 수치 | 값 (TEMP, 폰에서 조정) | 뜻 |
|---|---|---|
| tap_max_move_px | 12 dp | 누른 뒤 이만큼 안 움직이고 떼면 탭 |
| tap_max_time_s | 0.4 | 이보다 오래 누르면 탭 아님 (길게 누르기는 MVP에서 쓰지 않음) |
| swipe_min_dist | 화면 폭의 15% | 이만큼 밀면 방 넘기기 |
| swipe_min_speed | 화면 폭/초 × 0.8 | 짧아도 빠르게 밀면 넘김 |
| same_target_debounce_s | 0.3 | 같은 대상 연속 탭 무시 |
| drag_start_px | 12 dp | 판의 물건을 누른 채 이만큼 움직이면 끌기 시작 (탭 후보 취소) |
| drag_snap_radius | 칸 크기의 60% | 이 안에서 떼면 그 칸에 놓임 |
| drag_edge_wait_s | 0.5 | 화면 가장자리에 머물면 옆 방으로 |
| back_exit_window_s | 2.0 | 방 화면에서 뒤로 두 번 |

- **입력 버퍼:** 쓰지 않는다. 막혀 있는 동안의 입력은 버린다. UI 게임이라 미리 받아 둘 필요가 없다.
- **코요테 타임:** 해당 없음.
- **키 재설정:** 해당 없음.

## 동시 입력 · 우선순위
1. 두 손가락 이상이면 일러 확대 화면에서만 집기로 쓰고, 그 밖에서는 첫 손가락만 쓴다.
2. 판 위의 물건을 누르고 움직이면 **끌기**가 된다. 방 바닥을 누르고 움직이면 **밀기**(방 넘기기)가 된다. 둘이 한 누름에서 겹치지 않는다. 한 번 누름이 밀기와 탭 둘 다로 읽힐 수 있으면 **밀기가 이긴다**. 움직임이 12dp를 넘는 순간 탭 후보는 취소된다.
3. 탭한 지점에 대상이 겹치면 **정령 > 선물 > 그릇 > 칸** 순서로 하나만 받는다. 정령이 놀잇감 위에 있으므로 정령이 먼저다.

## 캔슬 규칙 (지금 일어나는 일 × 새 입력)

| 지금 | 새 입력 | 처리 |
|---|---|---|
| 방 넘기는 애니메이션 중 | 탭 | 무시 (넘김이 끝난 뒤부터) |
| 방 넘기는 애니메이션 중 | 반대쪽 밀기 | 무시 |
| 정령 반응 애니메이션 중 | 같은 정령 탭 | 무시 |
| 정령 반응 애니메이션 중 | 다른 대상 탭 | 받음 (반응은 계속 재생) |
| 정령 등장·퇴장 연출 중 | 그 정령 탭 | 무시 |
| 고르기 판 열리는 중(0.2초) | 판 안 탭 | 무시 |
| 일러 해금 연출 중 | 탭 | 다음 해금 또는 닫기만 |
| 끌기 중 | 다른 손가락 탭 | 무시 |
| 끌기 중 | 끌던 칸의 정령이 떠남 | 그대로 놓을 수 있음 |
| 끌기 중 | 앱이 백그라운드로 | 끌기 취소 (무변경) |
| 방치 계산 중 (P0 / 최대 2초) | 모든 게임 입력 | 무시 (뒤로는 앱 종료 규칙 그대로) |
| 구매 처리 중 | 사기 다시 탭 | 무시 (C7 보상 중복) |

## 입력 컨텍스트

| 컨텍스트 | 받는 액션 | 막는 것 |
|---|---|---|
| **Busy** (방치 계산, 화면 전환) | Back(종료 규칙만) | 나머지 전부 |
| **Room** (방 화면) | TapSpirit, TapGift, TapSlot, TapBowl, SwipeRoom, TapMenu, Back | |
| **Sheet** (고르기 판) | PickItem, DragItem, Dismiss, Back | 방 입력 (끌기 중에는 방 칸이 놓을 대상으로만 열림) |
| **Screen** (상점·도감·앨범·설정·일러 보기) | 화면 버튼, Buy, ZoomArt, Back | 방 입력 |
| **Modal** (확인 창, 일러 해금, 위치 안내) | 창 버튼, Dismiss, Back(= 닫기) | 뒤 화면 전부 |
| **Tutorial** (첫 안내) | 안내된 대상 하나 + Back | 안내 대상 외 전부 |

컨텍스트는 한 번에 하나만 활성화한다. 위로 쌓고, 닫으면 아래 컨텍스트로 돌아간다. 우선순위는 Busy > Tutorial > Modal > Sheet/Screen > Room이다.
