# X6 수익화 · 라이브옵스 · 분석 지표

> 2026-11-16 · 확정 (위임 결정 1·2 반영). 사용자 결정: **무료 + 광고 보상 / 유료 재화.** 유료 우위 범위는 위임 결정 2 (Sonnet max, 2026-11-16 — 위임결정-2.md) X-5. 결제 구현과 서버 구조는 책 범위 밖이며 0.9판에서 정한다.
> **MVP(0.2)에는 수익화가 없다.** 가설 시험판이기 때문이다.

## 수익 모델 (한 문장)
**무료로 하고, 원하면 광고를 보거나 유료 재화로 '더 예쁘게, 더 많이 보는' 것을 산다. 정령을 만나는 확률과 속도를 돈으로 크게 바꾸지는 않는다.**

## 상품 · 가치 · 공정성 (0.9판, X-5)

**원칙:**
- 모든 수집물(정령, 장면 일러, 달성 일러)은 이슬구슬로도 얻을 수 있어야 한다. 구슬 가격은 하루 수입의 3일치 이하다.
- 유료는 지름길과 꾸미기만 판다.
- 놓치면 영영 못 얻는 한정은 없다.
- 유료 → 구슬 교환은 고정 환율이고, 하루 상한은 그날 평균 수입의 1배다.
- 광고는 보상형만, 사용자가 누를 때만, 상점 안에서만 나온다. 열기와 닫기 직후, 방 화면 위에는 띄우지 않는다.
- 선물 배율과 확률 부스트는 금지한다.

| 상품 | 가치 | 공정성 판단 |
|---|---|---|
| 꾸미기 테마 (벽지, 바닥, 커튼 묶음) | 방이 예뻐짐 + 테마 전용 장면 일러 | 허용 (표현 상품, 필러 3) |
| 특별 방 (예: 온실 방) | 놓을 칸 + 그 방 전용 정령 1~2명 | 허용. **구슬 경로 필수** (하루 수입 3일치 이하), 전용 정령의 선물과 가중치는 일반과 같다 |
| 유료 재화 → 일반 재화 교환 | 놀잇감을 빨리 삼 | 허용. 고정 환율, 하루 상한 = 그날 평균 수입의 1배 (환율은 0.9 시뮬레이션에서) |
| 광고 보상: '손님 초대' | 1시간 동안 방문 판정 간격 ×0.7 | 하루 3회. 효과 수치는 0.9 시뮬레이션 전에 약속하지 않는다 (검토자 추정 +5% 안팎) |
| 광고 보상: 재화 꾸러미 | 재화 = 2시간분 | 하루 3회 |
| ✕ 가챠, 정령 확률 상품, 확률형 묶음 | - | **금지** (반필러) |

- **가격 데이터:** `data/iap.json` (상품 ID, 스토어 SKU, 유료 재화량, 표시 가격은 스토어가 줌).
- **영수증:** 서버에서 검증한다 (appdev-iap-backend 방식).

## 라이브옵스 (출시 뒤)
- **계절 이벤트:** 실제 계절과 명절에 맞춘 한정 정령, 놀잇감, 장면. 다음 해에 다시 온다. "놓치면 영영 못 얻는" 한정은 하지 않는다 (필러 2).
- **주기 (1.0 뒤):** TEMP 8주마다 정령 4, 놀잇감 2, 장면 2. 원칙은 '상위 25% 사용자의 도감 완성일 + 7일 안에 다음 판'이다.
- **점검:** 오프라인 게임이라 점검이 거의 없다. 서버는 날씨 서비스 상태와 결제만 신경 쓴다.

## 분석 지표

**MVP는 기기 안 시험 기록만 쓴다 (S14).** 정식판에서는 동의를 받고 분석 서비스를 쓴다.

| 이벤트 | 속성 | 시점 |
|---|---|---|
| `app_open` | 경과 시간(분), 방치 계산 방문 수, 빈 방 여부, 날씨 출처 | P1이 보인 직후 |
| `place` | toy_id, 방, 바꾸기 여부, 정령이 있던 칸인지, 직전 1시간 안에 도감 힌트를 봤는지 | 성공 시 |
| `fill_bowl` | food_id, 남아 있던 양 | 성공 시 |
| `gift_claim` | 재화량, 물건 | 성공 시 |
| `spirit_first` | spirit_id, 첫 실행 후 경과 시간(시간) | 해금 시 |
| `scene_unlock` | scene_id | 해금 시 |
| `buy` | product_id, 가격, 남은 재화 | 성공 시 |
| `photo` | 찍힌 정령 수 | 성공 시 |
| `book_open` · `card_view` | 탭, 대상 | 열 때 |
| `tutorial_step` | 단계, 건너뛰기 여부 | 단계 완료 시 |
| `session_end` | 길이(초) | 백그라운드로 갈 때 |

**핵심 지표 정의식:**
- **하루 열기 수** = 사용자별 하루 `app_open` 수의 평균 (D7 가설: 3 이상)
- **빈 방 비율** = `app_open(빈 방)` ÷ `app_open` (목표 10% 이하)
- **힌트 뒤 배치 변경 비율** = 7일 동안 '힌트를 본 뒤 1시간 안에 바꾸기'가 1회 이상인 사용자 ÷ 전체 (목표 50% 이상, 검토 위험 3)
- **아침 첫 열기 빈 방 비율** = 하루 첫 `app_open` 중 빈 방 ÷ 하루 첫 `app_open` (목표 20% 이하, 검토 위험 1)
- **열기 → 첫 조작 시간** = `app_open`에서 첫 탭까지 걸린 시간의 중앙값 (해금 팝업 부담 측정, 검토 위험 7)
- **D1, D7 잔존율** = N일째에 `app_open`이 있는 사용자 ÷ 설치 사용자
- **도감 진행 속도** = `spirit_first`의 경과 시간 분포 (G1 목표와 비교)
- **경제 흐름** = 하루 `gift_claim` 합계 대 `buy` 합계

## 개인정보 · 동의
- **MVP:** 기록은 기기 안에만 두고 밖으로 보내지 않는다. 시험 참가자가 직접 내보낸다.
- **정식판:**
  - 분석 동의 창을 띄운다.
  - 개인정보 처리방침을 둔다 (위치는 대략 좌표만, 날씨 조회에만 쓰고, 저장하지 않음).
  - 광고 SDK의 아동 설정을 맞춘다.
  - **처리방침은 출시 전 필수다** `[X8 마일스톤]`.

## 환불 · 복구 정책 (0.9)
- 스토어 환불 정책을 따른다.
- 환불이 확인되면 유료 재화를 회수한다. 음수는 0으로 둔다 (필러 2와 충돌하지만 결제 공정성이 먼저다).
- 기기를 옮길 때는 구매 복원 기능으로 비소모 상품(테마, 특별 방)을 복원한다.
