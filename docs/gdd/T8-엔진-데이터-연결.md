# T8 엔진 데이터 연결 (Godot 4.7.2 — 엔진 중립 3열 구조표 + Godot 대응)

> 2026-11-16 · 확정 (위임 결정 1·2 반영). 엔진(Godot 4.7.2)은 사용자가 정했다. 책의 ScriptableObject(SO) 자리를 Godot에서는 **JSON 정적 데이터 + 읽기 전용 Def 객체**로 대신한다.
> **JSON을 고른 이유:**
> - 사람과 도구가 같이 고치기 쉽다. 시뮬레이터(Python)도 같은 파일을 읽는다.
> - diff가 잘 보인다.
>
> 규칙 데이터는 모두 JSON이다. Resource(.tres)는 그림 묶음, 소리, UI 테마에만 쓴다 (위임 결정 2).

## 3열 구조표 (정의 / 런타임 / 저장)

| 대상 | 정의 (원본, 읽기 전용) | 런타임 (현재 상태, 실행 중) | 저장 (종료 후 유지) |
|---|---|---|---|
| 정령 | `data/spirits.json` → `SpiritDef` (Object, 읽기 전용 속성) | `Visit` (상태, phase, leave_at, reacting) | `visits_now`, `collection`, `pity` |
| 놀잇감·간식·방 | `data/toys.json`, `foods.json`, `rooms.json` → `ToyDef`… | placement 사본, 그릇 남은 양 계산 | `inventory`, `placement`, `food_bowls`, `rooms_owned` |
| 선물·상품 | `data/gifts.json`, `shop.json` | 선물 굴림 결과 (pending에 들어가기 전) | `pending_gifts`, `wallet`, `purchase_count` |
| 장면·친밀도 | `data/scenes.json`, `bonds.json` | 조건 검사 결과 | `scenes_unlocked`, (0.3) bond 해금 |
| 조정값 | `data/tuning.json` | - | - |
| 설정 | (기본값은 코드 상수) | Applied 값 | `settings.cfg` |

## 규칙
1. **원본 수정 금지:** `SpiritDef` 같은 Def 객체는 읽을 때 만들어지고, 실행 중에는 바꾸지 않는다 (setter 없음). 런타임 상태는 Def를 **ID로 가리키고**, 값이 필요하면 Def에서 읽는다.
2. **참조 방식 하나:** 데이터 사이의 참조는 항상 **ID 문자열**이다. 노드나 객체를 직접 참조하지 않는다. 저장도 ID로 한다.
3. **Catalog:** `sim/defs.gd`(K8)가 모든 Def를 ID → 객체 사전으로 들고 있는 유일한 카탈로그다. 'GameDatabase'처럼 모든 것을 아는 거대한 객체는 만들지 않는다. 카탈로그는 찾기와 검증만 한다.
4. **검증:**
   - 시작할 때 `Defs.validate()`가 T1 표를 검사한다. 개발 빌드는 Error면 멈추고, 출시 빌드는 경고를 남기고 해당 항목을 건너뛴다.
   - 같은 검증을 헤드리스 시험 묶음(`tests/data_tests.gd`)으로도 돌린다.
5. **Source of Truth 방향 (단방향):** `data/*.json`(원본) → 게임과 시뮬레이터가 읽는다. 스프레드시트를 쓰면 **스프레드시트 → JSON 내보내기** 한 방향으로만 한다. JSON을 직접 고친 내용은 스프레드시트에 되돌려 쓰지 않는다. MVP는 JSON 직접 편집이 원본이다. 0.3(정령 16명 이상)에서 다시 본다.
6. **상속 금지:** `ToyDef extends ItemDef` 같은 깊은 상속은 쓰지 않는다. 공통 필드 묶음 + 타입별 필드로 한다 (단순한 구성).
7. **사용자 데이터 경로:** 저장, 설정, 사진 경로는 한 곳(`UserPaths` 같은 도우미)에서만 만든다 (개발 규칙).
