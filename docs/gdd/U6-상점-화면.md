# U6 상점 화면 (P3)

> 2026-11-16 · 초안. 결과 코드는 G9를 따른다.

## 구조
- **위쪽:** 재화 영역 (보유량).
- **가운데:** 상품 목록. 2열 카드에 그림을 크게, 이름과 가격을 아래에 둔다. 위에서부터 놀잇감, 방, 간식 순서다.
- **상품 탭 → 구매 확인(Q4):** 그림, 이름, 한 줄 설명, 가격, '사기'와 '그만'.
- **메시지:** 결과 띠 (U8).
- **수량:** MVP는 한 번에 1개(또는 1묶음)만 산다. 수량 선택 기능은 없다.

## 상품 상태 6종 (상태는 Shop이 계산하고 UI는 보여 주기만 함)

| 상태 | 이유 (원본) | 카드 모습 | 탭하면 |
|---|---|---|---|
| Available | 조건 충족 · 재화 충분 | 보통 | Q4 |
| NotEnoughCurrency | 재화 < 가격 | 가격 글자 흐림 | Q4 (사기 버튼 흐림, "조금 더 모으면…") |
| InventoryFull | 보유가 상한 (간식 99) | '가득' 띠 | 띠만 |
| Locked | requires 미충족 | 그림은 보이고 자물쇠와 조건 글 ("놀잇감을 3개 모으면") | 띠만 |
| SoldOut / AlreadyOwned | 구매 제한 1회 이미 씀 | '가짐' 도장 | 아무 일 없음 |
| PurchaseLimitReached | (MVP에 해당 상품 없음) | '더는 없음' | 띠만 |

## 구매 시 로직 재검증
- Q4의 '사기'는 `Shop.buy(product_id)`를 요청한다. Shop은 G9의 1~5단계를 **다시 검사한다.**
- 확인 창이 떠 있는 동안 재화가 바뀌었다면(선물을 받은 경우 등) 그 결과를 따른다.

## 구매 후 갱신 범위
- **재화 영역**
- **그 상품 카드:** 가짐 또는 남은 수
- **다른 상품의 잠김 여부:** 놀잇감 개수 조건이 풀릴 수 있다
- **방 화면 배지와 소지품**
- **방을 샀다면:** 상점을 닫고 새 방으로 넘겨 주는 연출을 한다

## 결과 코드 ↔ 메시지 (G9와 1:1, 메시지 ID는 U8 목록)

| 코드 | 메시지 ID | 문구 |
|---|---|---|
| Success | `msg_buy_ok` / `msg_buy_room` | "○○을 들였어요" / "새 방이 열렸어요" |

| Locked | `msg_buy_locked` | "놀잇감을 더 모으면 열려요" |
