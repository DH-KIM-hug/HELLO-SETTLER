## 공통 규칙 (모든 개발 요청 앞에 붙는 별도 블록 — `docs/gdd/A2-공통규칙.txt`로 복사해 쓴다)

```
[공통 규칙 — 정령 손님 MVP (제목 미정)]
- 엔진: Godot 4.7.2, 2D, Mobile 렌더러, GDScript 정적 타입. 4.4 이후 API는 docs/engine-reference/godot/ 를 먼저 본다.
- 기준 문서: docs/gdd/ (D·C·K·G·U·T·F·X). 문서와 다르게 만들지 않는다. 문서에 없는 규칙이 필요하면 만들지 말고 '질문 목록'에 적는다.
- 구조: sim/ (규칙, 노드 모름, 헤드리스 시험 가능) · view/ (그리기·입력, 요청만) · platform/ (네트워크·권한) · data/ (정적 JSON). K8 책임표를 따른다.
- 값의 원본은 한 곳: 재화=Wallet, 파일=SaveStore, 방문=Visits, 수집=Collection. UI는 원본을 고치지 않는다.
- 검증 후 반영: 실패하면 아무것도 바뀌지 않는다. 보상은 한 곳에서 한 번만.
- 수치·문자열 하드코딩 금지: 수치는 data/tuning.json·*.json, 문자열은 data/text/ko.csv 키.
- 규칙 랜덤은 (save_seed, 용도, 번호) 해시에서만 (X3).
- 정적 변수(static var)로 게임 상태를 들지 않는다 (시험 격리).
- user:// 경로는 경로 도우미 한 곳에서만.
- 커밋하지 않는다(메인 세션이 한다). 시험 프로세스를 pkill 하지 않는다. 끝날 때까지 기다리며 턴을 끝내지 않는다.
- 끝에: 바꾼 파일 목록, 실행한 시험과 결과, 가정(Assumptions) 목록, 질문 목록.
```

## 기능 요청 11항 템플릿

```
1. 개발 환경: (공통 규칙 참조) + 이번 작업 트리/브랜치
2. 기능 목적: 한 문장 (어느 필러·루프 단계에 기여)
3. 현재 구조: 이미 있는 파일·클래스·신호 (경로)
4. 구현 요구: 번호 목록 (기획서 문장 그대로, 출처 표시 예: [K4 T5])
5. 사용 데이터: 읽는 정적 데이터 / 바꾸는 저장 데이터 (C5·G10)
6. 처리 흐름: F9 해당 흐름 그대로
7. 예외: F1 해당 표 그대로
8. 책임: 이 기능이 하는 것 / 하지 않는 것 (다른 시스템 몫)
9. 제약: 성능 예산(X8), 금지(공통 규칙)
10. 완료 조건: Given/When/Then 목록 (A6) + 헤드리스 시험 통과 + (화면이면) 스크린샷
11. 출력 형식: 바꾼 파일, 시험 결과, 가정, 질문
```

**최소 7항 버전 (작은 수정용):** 목적 · 현재 구조 · 요구 · 예외 · 책임 · 완료 조건 · 출력.

## 고정할 것 vs AI에게 맡길 것

| 고정 (기획서가 정함, 바꾸면 안 됨) | 맡김 (구현자가 정함) |
|---|---|
| 규칙, 순서, 우선순위, 수치 키 이름 | 내부 private 함수 나누기, 변수 이름 |
| 공개 API 이름(K8 후보, A4 확정 후) | 노드 트리 세부 구성 |
| 신호 이름과 인자 | 자료구조 선택 (사전/배열) |
| 저장 필드 이름 (G10) | 최적화 방법 (예산 안이면) |
| 결과 코드 이름 (G9, F1) | 시험 코드 구성 |
| 화면 ID와 전환 (U9) | 애니메이션 트윈 세부 (K6 시간 안) |
