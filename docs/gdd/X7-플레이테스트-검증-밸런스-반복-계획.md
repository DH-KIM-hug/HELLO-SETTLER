## 관찰 항목 (0.2 첫 10분은 화면 녹화나 옆에서 보기)
- 처음에 무엇을 누르는지, 첫 안내를 건너뛰는지
- 끌기를 쓰는지, 탭을 쓰는지
- 선물을 알아채는지, 도감을 찾는지
- 이해하지 못한 화면이나 문구 (말한 그대로 받아 적음)
- 언제 앱을 닫는지 (첫 세션 길이)

## 설문 (7일 뒤, 5분)
1. 하루에 몇 번쯤 열었나요? 왜 열었나요?
2. 가장 좋았던 순간은? (자유)
3. 가장 아쉬웠거나 헷갈렸던 것은?
4. 가장 좋아하는 정령은? 이유는?
5. 일러는 얼마나 예뻤나요? (1~5)
6. 비 오는 날 일부러 열어 본 적이 있나요?
7. 계속하고 싶나요? (1~5) 무엇이 더 있으면 좋겠나요?

## 변경 반영 절차
1. 결과를 가설별로 표에 정리한다 (`docs/gdd/playtest/<날짜>.md`).
2. 바꿀 것은 **한 번에 2~3개 변수만** 바꾼다. 예: 판정 간격과 선물량.
3. 변경은 `docs/gdd/changelog.md`에 기록한다: 무엇을, 왜, 어느 결과 때문에, 무엇이 기대되는지.
4. 해당 GDD 단계를 `reopen`한다 → 영향받는 단계를 다시 확인한다 → 시뮬레이션을 다시 돌린다 → 다음 판에서 다시 시험한다.

## 개발자 편향 방지
- 만든 사람(사용자, Claude)의 느낌은 내부 단계에서만 판단에 쓴다.
- 0.2 합격은 **외부 참가자 수치**로만 판정한다.
- 질문에 원하는 답을 유도하는 표현을 쓰지 않는다 ("귀엽지 않았나요?" 금지).
