## 상점의 역할
상점은 재화를 **새 질문**으로 바꾸는 곳이다 (C2 ⑤). 질문은 "이번엔 누가 올까"다. 효율 상품, 시간 단축, 확률 상품은 팔지 않는다 (반필러).

- **잠금:** 단계를 두어 한 번에 고를 것이 너무 많아지지 않게 한다 (힉의 법칙). 잠긴 상품도 그림과 '조건' 글은 보여 준다. 다음 목표가 보이게 하려는 것이다 (자이가르닉).
- **갱신, 랜덤 진열, 할인, 환불:** MVP에서 제외한다.

## 구매 흐름

```
상품 탭 → 확인 창(Q4: 그림·이름·가격·'사기'/'그만')
'사기' → Shop.buy(product_id):
  1) 상품 존재?             아니면 InvalidProduct
  2) requires 충족?         아니면 Locked
  3) 구매 제한 남음?        아니면 AlreadyOwned / LimitReached
  4) Inventory.can_add(target, qty)?  아니면 InventoryFull
  5) Wallet.can_spend(price)?         아니면 NotEnoughCurrency
  6) 거래: Wallet.spend + Inventory.add (+ 방이면 rooms_owned 추가) — 하나라도 실패하면 전부 되돌림 → InternalError
  7) 구매 기록 (purchase_count[product_id] += 1)
  8) 결과 Success → UI 갱신 (재화, '가짐' 표시) → 저장 표시
```

- **로직이 다시 검증한다:** 확인 창이 '사기'를 활성화했어도 Shop.buy는 1~5를 다시 검사한다 (UI는 원본이 아님).
- **연타:** 거래 중에는 '사기' 입력을 막는다 (K1). 끝나면 확인 창을 닫는다.

## 결과 코드 ↔ UI 메시지 (메시지는 UI 쪽 표, 로직은 코드만 돌려줌)

| 코드 | 화면 메시지 (거인 쪽 UI, 숫자 허용) | 바뀌는 것 |
|---|---|---|
| Success | (사는 소리) "○○을 들였어요" · 방이면 "새 방이 열렸어요" → 그 방으로 넘겨 줌 | 재화 −, 물건 + |
| NotEnoughCurrency | "조금 더 모으면 살 수 있어요" | 없음 |
| Locked | "놀잇감을 더 모으면 열려요" | 없음 |
| AlreadyOwned | (버튼 자리에 '가짐') | 없음 |
| LimitReached | "더는 살 수 없어요" | 없음 |
| InventoryFull | "꽃꿀이 가득해요" | 없음 |
| InvalidProduct · InternalError | "잠시 뒤에 다시 해 주세요" + 개발 로그 | 없음 |
