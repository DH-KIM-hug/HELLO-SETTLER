# X11 오프라인 진행 · 시간 처리 · 큰 수

> 2026-11-16 · 확정 (위임 결정 1·2 반영). 시계 조작을 허용할지는 F7 초안(위임 결정)을 따른다. 오프라인 효율은 **100%**다. 앱이 켜져 있을 때와 같은 규칙을 그대로 다시 실행한다. 큰 수는 없다.

## 틱 구조
- **켜져 있을 때:** 1초 고정 틱이다 (World). 판정 시각이 된 칸만 판정한다. 화면 애니메이션은 프레임 델타로 따로 돈다.
- **백그라운드:** 아무 일도 하지 않는다. 앱이 앞으로 돌아오면 방치 계산(S5)으로 따라잡는다.

## 오프라인 계산식
'생산률 × 시간'처럼 한 번에 곱하는 공식이 아니다. **같은 규칙을 시간순으로 다시 실행한다.**

```
경과 = clamp(now − last_seen, 0, offline_cap_s)
for 각 칸의 판정 시각 t (last_seen < t ≤ last_seen + 경과, 오름차순, 여러 칸을 섞어 시간순):
    S3.consume(t)   # 그릇: 수줍은 정령 몫(앱 꺼짐 = 전부 해당) + 와 있는 정령 몫
    S4.leave_due(t) # 머무는 시간이 끝난 정령 → Leaving(0초) → 선물 생성
    S4.check(slot, t, env=S1.at(t))
```

| 항목 | 값 |
|---|---|
| `offline_cap_s` | **24시간** (메인 판단 2026-11-16, 개발 7일 시나리오 근거: 12시간이면 밤샘·근무 공백이 잘려 둘째 방이 6.5일 넘게 늦어짐). 기본 그릇도 24시간이라 상한과 그릇이 같은 기준이 된다 |
| 효율 | 100% (같은 규칙) |
| 판정 수 | 칸 7 × 144(24시간 ÷ 10분) ≈ 1,000회 → 예산 200ms (X8, 12시간 실측 39ms) |
| 지난 시간의 날씨 | `S1.at(t)`: 마지막 조회 때 캐시한 **시간별 예보 24칸** 안이면 그 값, 아니면 시드 날씨. 지난 날씨를 서버에 다시 묻지 않는다 |
| 지난 시간의 낮/밤 | 현지 시각 t로 계산 (위치가 있으면 그 지역의 해 뜨고 지는 시각, 없으면 6시와 19시) |

## 시계 조작 방침 (F7 초안)
- 경과 시간이 음수면 0으로 하고 `last_seen = now`로 다시 기준을 잡는다 (F-1).
- 경과 시간이 상한을 넘으면 상한에서 자른다. 한 번 조작할 때 이득은 24시간분에 그친다 → **허용** (F-1, 혼자 하는 게임).
- **방치 계산 중에도 이벤트를 시간순으로 바로 처리한다** (선물, 도감). 그래서 그 사이 처음 만난 정령의 '만난 시각'이 정확하고, 첫 만남 보장과 R2도 바로 반영된다 (개발 검증에서 발견).
- 단조 시계 보조: 앱이 켜져 있는 동안 `Time.get_ticks_msec()`로 벽시계가 크게 튀는지 감지한다. 튀면 그 구간을 상한 규칙으로 처리하고 기록한다.
- 서버 시간: 쓰지 않는다 (MVP). 0.9판 유료 재화는 서버 영수증 기준이라 시계와 무관하다.

## 큰 수 · 자료형
- **큰 수는 없다.** 재화 상한이 99,999(G8 위임 결정)라서 64비트 정수로 충분하다.
- 시각은 64비트 정수(초)로 다룬다.
- 확률과 배율은 64비트 실수다.
- **표기:**
  - 재화는 천 단위 쉼표 (1,240). K, M, B 표기나 과학 표기를 쓰지 않는다.
  - 정령 쪽에는 숫자를 표시하지 않는다.
- **정밀도:**
  - 그릇 양은 실수다. 0.001 미만이면 0으로 본다 (K7).
  - 시각 비교는 정수로만 한다.

## 저장 형식
- 정수와 시각은 JSON 숫자로 저장한다 (2^53 미만이라 안전).
- last_seen은 UTC 초 정수다.

## 복귀 화면 (수령 요약)
- 따로 '보상 요약 창'은 두지 않는다. **방 자체가 요약이다.** 와 있는 정령, 칸 옆 선물, 그릇 상태, 부스러기가 보인다 (필러 1).
- 새 정령이나 새 일러는 해금 팝업 대기열(U8)로 보여 준다.
- 보이지 않는 방에 선물이 있으면 방 표시점에 작은 점을 찍는다 `[U 반영]`.

## 로드 검증 테스트
1. 경과 0초, 1분, 판정 간격 ±1초, 12시간, 12시간 + 1초, 3일: 결과가 상식적이고, 상한 뒤로는 변화가 없다.
2. 같은 저장 파일과 같은 now로 두 번 계산하면 결과가 같다 (결정적 난수).
3. 시계를 1일 뒤로 돌리면 아무것도 바뀌지 않는다.
4. 12시간 계산이 최소 사양 기기에서 200ms 이하다.
