# K8 기획 → 코드 구조 (책임표)

> 2026-11-16 사용자 확정. 클래스 이름은 제안이며, 규칙과 책임은 기획서가 정한다. 과도한 추상화는 하지 않는다.
> **분리 원칙:**
> - 설정 데이터(정적 파일), 런타임 상태(저장 대상 포함), 로직을 나눈다.
> - 화면과 입력은 **요청**만 보낸다.
> - `sim/`(규칙)은 화면 노드를 모른다. 그래서 창 없이 시험할 수 있다.

## 데이터 흐름 (요청 → 검증 → 반영 → 알림)

```
터치 → InputRouter (컨텍스트 확인) → 요청(예: claim_gift(slot))
     → World → Wallet.claim(slot)  [검증: pending에 있나]
             → 반영: pending 삭제 + coins 증가 (한 번에)
             → SaveStore.mark_dirty()
             → 신호 gift_claimed → View(선물 표시 지우기), Feedback(소리)
```

## 의존관계 (화살표 = 부른다 / 안다)

```
view/* ──▶ sim/world ──▶ sim/{visits, food_bowls, placement, collection, wallet, shop, catch_up, env_clock}
                         sim/catch_up ──▶ visits, food_bowls, env_clock
                         sim/visits ──▶ placement, food_bowls, env_clock, defs   (wallet·collection에는 '신호'로만 알림)
                         sim/shop ──▶ wallet, inventory, placement(방 열기)
                         sim/* ──▶ save_store (dirty 표시만)
platform/weather_service ──▶ (아무 sim도 모름) ◀── sim/env_clock 이 결과만 받음
```

- **순환 없음:** visits는 wallet·collection을 직접 부르지 않는다. 신호를 보내면 world가 연결한다. sim은 view를 모른다.

## 구조로 검증하기 (공격·피격 흐름 대신 '방문' 흐름)

1. **판정:** world 틱 → visits.tick(now). 칸마다 판정 시각이 되면 후보를 거르고(placement, food_bowls, env_clock), 가중치를 매기고, 뽑는다. Away → Arriving(보이는 방) 또는 Playing.
2. **떠남:** leave_at → Leaving 진입 → 신호 `spirit_left(spirit, slot)`. world가 받아 wallet.create_gift(...)와 collection.count_visit(...)를 부른다. 각각 1회다.
3. **열기:** catch_up.run(last_seen, now) → 같은 visits.tick을 시간순으로 부른다. 결과를 반영한 뒤 view가 Restore로 그린다.
4. **처음:** Playing 진입 → 신호 `spirit_settled` → collection.on_seen(spirit, toy) → 처음이면 `unlocked(card)` 신호 → view가 Q1·Q2를 띄운다.

## 구조 질문으로 발견한 기획 빈칸

| 질문 | 기록 |
|---|---|
| 정령이 '처음 온' 시점은 Arriving 시작인가, Playing 진입인가? | **Playing 진입**으로 정함. 방치 계산(Arriving 0초)과 같은 규칙이 된다 |
| 보이지 않는 방에서 처음 온 정령의 새 손님 띠는 언제 띄우나? | 그 방을 처음 볼 때 띄운다 (U8) |
| 방치 계산 중에 처음 온 정령이 여럿이면 일러 해금 연출 순서는? | 처음 온 시각 순, 한 번에 하나, 연속 3개 (4개 이상이면 요약 카드, U8) |
| 사진은 sim이 찍을 수 없다 (화면 캡처) | 캡처는 view, 목록과 '찍힌 정령' 기록은 sim으로 나눔 |
| 날씨 조회가 응답하기 전에 방문 판정이 오면? | 마지막 캐시 또는 대체 날씨로 판정한다. 응답은 다음 판정부터 적용한다 |
| 1초 틱이면 판정 간격보다 촘촘한가? | 판정 간격 600초(T7)라 1초 틱으로 충분하다 |
