# F4 저장 · 불러오기

> 2026-11-16 · 확정 (위임 결정 1·2 반영). 저장 대상은 G10의 '저장' 분류와 같다. 저장 시점과 범위는 아래 표(위임 결정 대상).

## 저장 대상
G10 표에서 분류가 '저장'인 값만 저장한다. 모두 **ID와 수, 시각**이다.
- 그림, 노드, Def 객체는 저장하지 않는다.
- 파생값은 저장하지 않는다.

## 파일 분리

| 파일 | 내용 | 수명 |
|---|---|---|
| `save.json` (+ `save.bak`) | 진행 데이터 전부 | '처음부터 다시' 때 초기화 |
| `settings.cfg` | 설정 | 남김 |
| `photos/*.jpg` + 목록은 save.json 안 | 사진 | '처음부터 다시' 때 삭제 |
| `playtest_log.jsonl` | 시험 기록 | 남김 |

경로는 사용자 데이터 경로 도우미 한 곳에서 만든다 (T8 규칙 7).

## 저장 시점표 (종료할 때만 저장하는 데 의존하지 않는다)

| 사건 | 저장 |
|---|---|
| 놓기, 빼기, 그릇 채우기 | 표시 → 0.5초 묶음 |
| 선물 받기, 구매 | 거래가 끝난 **뒤** 표시 → 0.5초 묶음 |
| 정령 도착·떠남, 해금 (앱이 켜져 있는 동안) | 표시 → 0.5초 묶음. 최대 10초에 한 번 |
| 방치 계산 끝 | 즉시 |
| 백그라운드로 감 / 종료 | 즉시 (last_seen 포함) |
| 사진 찍기 | 파일 쓰기 성공 뒤 즉시 |
| 첫 안내 단계 완료 | 즉시 |

**거래 중간에는 저장하지 않는다.** 저장은 표시만 해 두고, 거래가 끝난 뒤에 쓴다.

## 쓰기 방식
1. `save.tmp`에 쓰고 flush한다.
2. 기존 `save.json`을 `save.bak`으로 바꾼다.
3. `save.tmp`를 `save.json`으로 바꾼다.
4. **결과:**
   - `SaveResult = Ok | DiskFull | IoError`
   - 실패하면 메모리 상태는 그대로 두고 다음 묶음에서 다시 시도한다.
   - 3번 연속 실패하면 띠를 1회 띄운다.

## 불러오기
1. `save.json`을 읽고 JSON 파싱과 `save_version`을 확인한다.
2. 실패하면 `save.bak`을 읽는다. 그것도 실패하면 U2 분기(broken 보관 → New Game)로 간다.
3. **버전 변환:** `v1 → v2 → …`를 차례로 적용한다. 각 변환은 순수 함수다.
4. **검증:** G10 검증 규칙과 T3 지운 ID 정책을 적용한다. 검증을 통과한 결과로 **한 번에 교체**한다. 일부만 적용하는 일은 없다.
5. `LoadResult = Ok | RecoveredFromBackup | Migrated | NewGame(reason)`
6. **불러오기 순서는 G10을 따른다:** 정의 → 저장 → 파생 → 방치 계산 → 그리기.

## Checkpoint와 Save
체크포인트는 없다. 모든 상태가 곧 저장 상태다.
