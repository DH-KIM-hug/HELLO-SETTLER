# F1 예외 조건 (기능별 표)

> 2026-11-16 · 초안. C7(사용자 확정)을 기능별로 확정한다. 검사 순서와 피드백은 K3·G9·U8을 따른다.
> **공통:**
> - 실행 직전에 시스템이 다시 검증한다. UI 버튼이 활성화돼 있어도 그것이 최종 검증은 아니다.
> - 실패하면 아무것도 바뀌지 않는다. 일부만 실행되는 일은 없다.
> - 모든 상태 변경 기능은 Result Code를 돌려준다.
>
> **Expected Failure와 Data Error는 다르게 처리한다.**
> - **Expected Failure:** 재화 부족처럼 정상적인 거절이다. 띠로 알린다.
> - **Data Error:** 없는 ID처럼 데이터가 잘못된 경우다. 개발 로그를 남기고 `msg_retry`를 띄운다.

## 기능별 표

### place(slot, toy) — 놀잇감 놓기·바꾸기
| 조건 | 검사 시점 | 처리 | 데이터 변경 | 피드백 | Result |
|---|---|---|---|---|---|
| 컨텍스트가 Sheet가 아님 / Busy | 입력 | 무시 | 없음 | 없음 | Ignored |
| 칸이 열린 방에 없음 | 실행 직전 | 거절 | 없음 | 개발 로그 | InvalidSlot (Data Error) |
| 칸 종류가 그릇 | 실행 직전 | 거절 | 없음 | 끌기 되돌림 | WrongSlotType |
| 놓을 수 있는 수 0 | 실행 직전 | 거절 | 없음 | 카드 흐림 | NotAvailable |
| 같은 칸에 같은 놀잇감 | 실행 직전 | 무시 | 없음 | 없음 | NoChange |
| 칸에 정령이 노는 중 (바꾸기) | 실행 | 정령 ForceLeave → 놓기 | placement, visits_now, pending_gifts(+1) | 손 흔들기 | Success |
| 정령이 온 지 60초 안 (악용 방지) | 실행 | 선물을 재화 1로만 | 위와 같음 | 같음 | Success |
- **Pre:** 칸이 존재한다. 놀잇감이 inventory에 있다.
- **Post:** placement[slot] = toy이고, 같은 놀잇감이 두 칸에 있지 않다 (종류당 1개인 경우).

### remove(slot)
| 조건 | 처리 | 변경 | Result |
|---|---|---|---|
| 칸이 비어 있음 | 무시 | 없음 | NoChange |
| 정령 있음 | ForceLeave → 비우기 | placement, visits_now, pending | Success |

### fill_bowl(slot, food)
| 조건 | 검사 시점 | 처리 | 변경 | 피드백 | Result |
|---|---|---|---|---|---|
| 칸이 그릇이 아님 | 실행 직전 | 거절 | 없음 | 개발 로그 | WrongSlotType |
| 좋은 간식 보유 0 | 실행 직전 | 거절 | 없음 | 흐림 + 상점 안내 | NotEnough |
| 같은 간식이 이미 가득 (≥ 0.999) | 실행 직전 | 무시 | 없음 | 없음 | NoChange |
| 좋은 간식이 남은 그릇을 다른 것으로 | 실행 직전 | 확인 창 → 확인 시 진행 | 그릇, (G5 결정에 따른 환불) | cf_swap_food | Success / Cancelled |
| 정상 | 실행 | 그릇 갱신 → **성공한 뒤** 보유 −1 | food_bowls, inventory | 반짝 | Success |

### claim_gift(slot | all)
| 조건 | 처리 | 변경 | Result |
|---|---|---|---|
| 방치 계산 중 | 무시 | 없음 | Busy |
| pending에 없음 (이미 받음) | 무시 | 없음 | AlreadyClaimed |
| 재화가 상한을 넘음 | 넘는 몫을 버리고 지급 (G6 정책) | wallet = 상한 | Success (Overflow 표시) |
| 간식이 99를 넘음 / Keepsake 중복 | 재화로 바꿔 지급 (G6) | wallet | Success |
| 정상 | pending 삭제 + 지급을 한 거래로 | pending, wallet, inventory, collection | Success |

- **검사 순서:** 존재 → 잠김 → 제한 → can_add → can_spend → 거래.

### capture_photo()
| 조건 | 처리 | 변경 | Result |
|---|---|---|---|
| 찍는 중 | 무시 | 없음 | Busy |
| 저장 공간 부족 / 파일 쓰기 실패 | 거절. 게임 저장은 계속 | 없음 | NoSpace |
| 정상 | 파일 쓰기 성공 **뒤에** photos 목록에 추가 (+ S7 '찍힌 정령') | photos | Success |

### delete_photo(id)
| 조건 | 처리 | 변경 | Result |
|---|---|---|---|
| 없는 id | 무시 | 없음 | NotFound |
| 정상 | 확인 창 → 목록에서 삭제 → 파일 삭제 (실패하면 목록만 지우고 다음 실행 때 고아 파일 정리) | photos | Success |

### unlock (S7 — 시스템 내부)
| 조건 | 처리 | 변경 | Result |
|---|---|---|---|
| 이미 해금됨 | 무시 | 없음 | AlreadyUnlocked |
| 그림 파일 없음 (출시 판) | 해금은 기록하고 회색 실루엣 + 경고 | collection | Success (경고) |

### catch_up (S5)
| 조건 | 처리 | 변경 |
|---|---|---|
| 경과 시간 < 0 (시계 되돌림) | 0으로 처리. last_seen은 바꾸지 않음 | 없음 |
| 경과 시간 > 상한 | 상한까지만 계산 | 상한까지 |
| 계산 중 예외 | 그 회차를 건너뛰고 last_seen만 갱신 (C7) | last_seen |

### reset_game
- **확인:** Q8을 두 번 받는다.

## 중복 · 경계 (포함 확인)
- **중복:**
  - 선물 연타 → AlreadyClaimed
  - 구매 연타 → 입력 막음과 재검증
  - 해금 두 번 → AlreadyUnlocked
  - 방치 계산 두 번 → last_seen을 먼저 갱신
- **경계:**
  - 재화 = 가격 / 가격 − 1
  - 간식 98 + 묶음 3
  - 그릇 0.001
  - 경과 시간 0 / 상한 ± 1초
