# Game Concept: 나의 작은 지구 (My Little Earth)

> 작성: /brainstorm (rigor full, 2026-11-07). 기존 기획서 `docs/GAME_DESIGN.md`·`docs/PLAYER_JOURNEY.md`를 근거로 이 틀에 다시 정리했다. 세부 규칙은 그 문서들이 기준이고, 이 문서는 콘셉트·기둥·범위의 정식본이다.
> 감독 점검: CD-PILLARS = CONCERNS → 반영 후 확정 · AD-CONCEPT-VISUAL = CONCEPTS → 사용자 선택 · TD-FEASIBILITY = CONCERNS · PR-SCOPE = OPTIMISTIC → 조정 반영.

## Elevator Pitch

유리병 속 소인의 세상을 거인(플레이어)이 지켜보며 돕는 모바일 3D 마을 시뮬레이션. 키 5cm 사람들이 거대한 꽃숲 아래서 밀을 거둬 빵을 굽고 길을 따라 나르며 살아가고, 거인은 몇 안 되는 손길로 위기를 넘기게 돕고 공물을 받는다. 그리고 그 사람들은 언젠가 하늘의 나를 알아본다.

**10초 시험**: "정착 시뮬 같은데, 그 사람들이 5cm이고, 내가 짓는 게 아니라 그들이 스스로 살며, 언젠가 하늘의 나를 알아본다."

## Core Identity

| 항목 | 내용 |
|---|---|
| 장르 | 아늑한 관찰형 마을 시뮬레이션 (신 시점 돌봄 + 일부 탐험) |
| 플랫폼 | 모바일 (Android 먼저, iOS 나중) |
| 엔진 | Godot 4.7.2 (GDScript) — 사용자 선택 |
| 시점 | 정사영 약 48° 지도 시점, 병 밖(거인의 방) ↔ 병 안(땅) 끊김 없는 확대 |
| 세션 | 5~15분 자주 + 가끔 30~60분, 비운 동안에도 병 시간이 흐름 (12시간 = 병 3일) |

| 예상 범위 | Large (첫 출시 4~5개월, 1인 개발 + AI 에이전트 팀), 전체 꿈 1~2년 |
| 수익 모델 | 보류 |

## Core Fantasy

**작은 세상의 다정한 신.** 손바닥만 한 유리병 안에, 끝이 안 보이는 작은 지구가 있다. 그 안의 사람들은 나를 모른 채 꽃 그늘 아래서 집을 짓고, 밀을 지고, 송사리를 둘이 메고 온다. 나는 명령하지 않는다. 마른 밭에 물을 뿌려 주고, 배고픈 날 낟알 한 줌을 내려 주고, 커다란 물방울이 떨어지기 전에 유리를 톡 쳐 준다. 어느 날 한 아이가 하늘을 가리키고, 노인부터 무릎을 꿇고, 그들은 내게 제단을 쌓는다. 이름이 남고, 아이가 태어나고, 세대가 이어진다.

---

## Unique Hook

"마을 경영 게임 같은데, **내가 짓지 않는다** — 그리고 **사는 사람들이 5cm이고, 언젠가 나를 알아본다**."

- 빼기가 아닌 더하기의 훅: 5cm 소인의 실감(꽃숲·송사리·개미 떼) + 화면으로 보이는 생산 사슬(밀→밀가루→빵을 손에 들고 나름) + 알아봄(깨달음·소원·공물).
- 가까운 장르 이웃(Reus·From Dust 같은 '신은 환경을 바꾸고 사람은 스스로 산다' 계열)과 다른 점은 이 조합이다. 특정 게임의 그림·이름·화면은 가져오지 않는다.

## Player Experience Analysis (MDA Framework)

### Target Aesthetics (What the player FEELS)
1. **순종(Submission) — 편안히 빠져듦** (주): 나르고 일하는 모습을 멍하니 보는 즐거움.
2. **판타지(Fantasy)**: 작은 세상의 다정한 신.
3. **발견(Discovery)**: 안개 너머의 땅, 큰 나무 다섯(소나무·과일·은행·단풍·벚), 처음 보는 꽃·생물.
4. **이야기(Narrative)**: 이름·연애·혼례·아기·죽음·연대기.
5. 곁들임 — 도전(Challenge): 빠듯한 때·위기를 손길로 넘김.

### Key Dynamics (Emergent player behaviors)
- 주민 하나를 따라가며 하루를 구경한다 (따라가기).
- 막힌 곳(쌓인 밀가루, 빈 창고)을 *화면에서* 알아채고 손길·설계도로 푼다.
- 언제 도울지, 그냥 둘지 고른다 (너무 자주 손대면 두려움).
- 비웠다 돌아와 편지로 "무슨 일이 있었나"를 확인하고 다음 목표를 정한다.
- 주민이 안개를 걷는 쪽을 지켜보며 큰 나무에 닿기를 기다린다.

### Core Mechanics (Systems we build)
- 창조 오프닝(버튼으로 지구 빚기) · 스타터킷(거인이 한 번 직접 놓음)
- 자율 주민 AI (일·나르기·관계·연애·출생·죽음) · 생산 사슬 (밀→맷돌→밀가루→공용 화덕→빵)
- 닫힌 병의 물·빛·이슬·소금 시뮬레이션 · 소인의 꽃숲·큰 나무 다섯
- 거인의 손길 (내려 주기·물 뿌리기·유리 닦기·핀셋·등불 옮기기·유리 톡) — 사건 때 하나씩 열림
- 깨달음·제단·공물·지폐·설계도·소원 들어주기·계시(가르침 고르기)
- 위기 (곰팡이·떠돌이 물방울·개미 군단) · 애벌레 사냥 · 거대 과일
- 안개를 주민이 걷음 (망루·나들이·분가) · 비운 시간 따라잡기 + 돌아온 편지 · 연대기

## Player Motivation Profile

### Primary Psychological Needs Served
- **자율성**: 언제·무엇을 도울지 거인이 고른다. 주민도 스스로 산다 (서로의 자율).
- **유능감**: 막힌 곳을 보고 풀어 마을이 시대를 오르고, 위기를 잘 넘긴다 (화면으로 확인).
- **관계성**: 이름 붙은 주민과의 정, 나를 알아봐 줌. 나중엔 친구의 선반.

### Player Type Appeal (Bartle Taxonomy)
- **탐험가 (주)**: 안개·큰 나무·발견 도감.
- **창작가·사교가 (곁)**: 나만의 지구(창조·이름·지구 카드), 나중 친구 선반.
- **성취가 (약하게)**: 시대·목표 사다리.
- **경쟁가**: 대상 아님.

### Flow State Design
- 첫 10분: 30초마다 거인의 수첩 쪽지 하나 (직관적인 일만), 첫 오두막 약 30초, 첫날 약 12분.
- 도전은 '빠듯함' 곡선으로: 60일에 2~4번 빠듯한 때 (겨울·아기 무렵·인구 증가), 도우면 넘김.
- 지루함 방지: 중요한 일이 생기면 저절로 느려지고 까닭을 말함. 불안 방지: 거인이 그냥 둬도 마을이 무너지지 않음.

## Core Loop

### Moment-to-Moment (30 seconds)
확대해서 주민을 따라간다 — 밀 단을 지고, 맷돌을 돌리고, 송사리를 메고, 대화 말풍선. 손을 쓰면 곧바로 반응 (톡 → 올려다봄, 낟알 → 달려옴).

### Short-Term (5-15 minutes)
병의 하루 한 바퀴 (보통 = 현실 5분): 새벽 이슬 → 일 → 저녁 모닥불. 작은 필요 1~2번 (배고픔·마른 밭·소원 편지) → 돕거나 둔다. '하루만 더'는 진행 중인 일(짓는 집·곧 태어날 아기·자라는 밀)에서.

### Session-Level (30-120 minutes)
큰 사건 하나 (깨달음·첫 빵·혼례·개미 떼) + 공물 받아 지폐로 설계도 + 안개 한 조각이 걷힘. 그만두는 지점은 밤. 다음 훅은 등불 시간·진행 중인 일·알림.

### Long-Term Progression
개척기 → 마을 → 읍내 시대, 큰 나무 다섯에 하나씩 닿기, 분가로 새 마을, 두 번째 병. 끝은 없고 세대를 잇는 연대기가 남는다.

### Retention Hooks
- 비운 동안 흐르는 병 + 돌아온 촌장의 편지
- 진행 중인 일 (아기·건물·안개)
- 이름 붙은 주민과의 정 (잃고 싶지 않음)
- 연대기·지구 카드 (내 지구의 역사)
- 나중: 친구의 선반

## Game Pillars

### Pillar 1: 스스로 살고, 나를 알아보는 사람들
주민은 거인 없이도 살아가고, 이름·세대·연대기가 남으며, 언젠가 하늘의 거인을 알아본다.
- **기준**: 직접 시키기 vs 스스로 하게 → 스스로 (거인은 조건을 바꾼다). 이야기(연대기·세대)를 줄일까 → 지킨다.

### Pillar 2: 보는 것이 곧 재미
일하고 나르고 사는 모습이 눈에 보인다. 처음 알아채는 신호는 늘 화면 속 행동이고, 숫자는 거인 화면에서 확인용.
- **기준**: 숫자로 알리기 vs 행동으로 보이기 → 행동. 막힌 곳이 *보여서* 찾아낼 수 있게.

### Pillar 3: 작은 세상의 실감
5cm 소인, 닫힌 병의 물·빛이 진짜로 돈다. 생물끼리의 비율과 '왜'는 진짜로, 화면에 보이는 크기는 잘 보이게 조정해도 된다.
- **기준**: 편한 단순화 vs 세상의 이치 → 이치 (보이는 크기만 예외).

### Pillar 4: 의미 있는 손길
거인의 손짓(행동 종류)은 적게, 하나하나 분명한 까닭·결과·대가. 내려 줄 물건(내용)은 늘려도 된다.
- **기준**: 손짓 추가 vs 있는 손짓 깊게 → 깊게. (감싸기·커튼·불기를 없앤 이유)

### Pillar 5: 안개 너머의 설렘
세상은 처음부터 다 보이지 않는다. 안개는 주민이 걷고(망루·나들이·분가), 거인은 안개 속 윤곽·소리를 구경한다.
- **기준**: 다 보여 주기 vs 발견하게 → 발견하게.

**기둥 사이의 건강한 긴장**: 1↔4 (혼자 잘 살수록 손길이 가벼워짐 → 믿음 감소·소원 편지로 이음), 2↔5 (안개가 볼거리를 가림 → 윤곽·소리), 2↔3 (실제 비율은 안 보임 → 보이는 크기 예외), 4↔상점 (물건이 늘면 손길이 가벼워짐 → 손짓과 물건을 나눔).

### Anti-Pillars (What This Game Is NOT)
- 주민에게 직접 명령하지 않는다, 주민이 짓는 건물의 터를 정하지 않는다 → 기둥 1. (맨 처음 스타터킷만 거인이 놓고, 하늘에서 내려 준 건물도 주민이 알아서 예쁜 자리에.)
- 주민 쪽 화면에 숫자·확률을 드러내지 않는다 → 기둥 2.
- 피 흘리는 전투·짐승 사냥을 하지 않는다 (개미 떼는 막아 내기, 사냥은 애벌레) → 소인 세상의 다정함.
- 의미 없는 손짓을 넣지 않는다 → 기둥 4.
- 인종 이름을 쓰지 않고, 겉모습은 능력과 상관없다.

## Visual Identity Anchor

**방향: 「꽃그늘 아래」 (+ 관찰 수첩의 안개, 손때 묻은 살림의 재료)** — AD-CONCEPT-VISUAL에서 사용자 선택.

- **한 줄 규칙**: 화면 안에는 언제나 주민보다 훨씬 큰 것이 있고, 그 그늘이 마을 위에 떨어진다.
- **원칙 1 — 세부 밀도를 거꾸로**: 큰 자연(꽃·풀대·다섯 나무)은 크고 단순한 곡선, 소인의 것(집·수레·짐)은 촘촘한 작은 반복. *기준: 이 모델이 큰가? → 세부를 줄인다. 소인의 것인가? → 이음매를 보인다.*
- **원칙 2 — 안개는 칠하지 않은 스케치**: 미개척지는 선만 있는 스케치로 보이다가, 주민이 밟으면 그 땅에 색이 번진다. *기준: 아직 주민이 모르는 것인가? → 색을 빼라.*
- **원칙 3 — 주워 온 색**: 마을의 색은 자연에서 가져온 것(마른 풀·흙·조약돌), 꽃잎 지붕은 그 철에 주운 꽃 색이라 계절 따라 바뀜. 주민이 만드는 색은 물들인 옷 하나. *기준: 이 색을 주민이 어디서 구했나?*
- **색 철학**: 바탕(땅·이끼·그늘)은 차분한 민트·세이지·청록. **고채도는 철마다 피는 꽃만.** 꽃 아래 그늘은 꽃 색으로 물든다 (장미 아래 분홍 청록). **거인의 손길은 유리의 흰빛·은청색** (꽃 색과 겹치지 않게).
- **열린 문제 (아트 바이블에서)**: 꽃이 마을 위로 솟으면 주민을 가림 ↔ 늘 보여야 함 — 카메라 쪽 꽃 반투명/줄기만, 또는 꽃은 가장자리·그늘만 안으로. 크기감은 높이 대신 그림자·세부 밀도·움직임으로.

## Target Player Profile

- **주**: 아늑한 시뮬·정원 가꾸기·관찰을 좋아하고, 짧게 자주 들여다보는 모바일 플레이어 (탐험가·창작가형).
- **곁**: 주민의 사랑·세대 이야기를 따라가는 이야기꾼형.
- **아님**: 빠른 경쟁·직접 조작·효율 극대화만 원하는 사람.
- 원하는 감정: "나 없을 때도 잘 살고 있었구나" 하는 안도와 정, "드디어 큰 나무에 닿았다"는 설렘.

## Technical Considerations

- Godot 4.7.2, GDScript, Mobile 렌더러, 셀 셰이딩 + 외곽선, 로우폴리 3D (블렌더 빌드 스크립트), 소리 ElevenLabs.
- 결정론 시뮬 (같은 기기 안), 헤드리스 시험 스위트, 자동 저장, 비운 시간 따라잡기 (시간 나눠 돌림, 편지 뒤에서).
- 넓은 세상 지름 1,024칸, 물은 고운(마을)·거친(8×8) 두 단계 계산.
- **예산 (안, TD 권고 — 실측 뒤 ADR로 확정)**: 30fps, 시뮬 ≤ 8ms·렌더 ≤ 20ms, 그리기 호출 ≤ 300, 화면 삼각형 ≤ 30만, 보던 병의 6일 따라잡기 ≤ 10초, 앱이 뒤로 갈 때 저장 ≤ 100ms. 기기 사이 결정론은 약속하지 않는다 (상태 전체 저장만 넘김).

## Risks and Open Questions

### Design Risks
- 초반 "할 게 없다" — 수첩 쪽지·사건 연출·도구가 사건과 함께 열림으로 대응, 플레이테스트로 확인.
- 자율성이 지나치면 손길의 의미가 약해짐 (기둥 1↔4) — 빠듯함 곡선·믿음·소원으로 잇기.
- 꽃숲이 마을을 가림 (그림 방향 ↔ 보는 재미).

### Technical Risks (TD-FEASIBILITY: CONCERNS)
- 폰 프레임 (꽃 인스턴싱·건물 폴리곤·주민 30명·외곽선·그림자) — **실측 최우선 (A15)**, LOD·저사양 단계.
- 폰 따라잡기 (추정 15~22초 + 열로 2~3배) — 실측, 보던 병만 정밀, WorkerThreadPool 검토, 상한 10초 넘으면 B11 앞당김.
- GDScript 계산 한계 → 물 계산 C++(GDExtension) 탈출구 (iOS 빌드와 묶어 결정).
- 연대기 크기·저장 속도, iOS 미시도, APK 70MB, 배터리·발열(30fps 상한·절전), 각진 먼 강.
- **VIABLE로 올라가는 기준**: 중저가 폰에서 주민 30명 장면 30fps, 6일 따라잡기 10초 안.

### Market Risks
- 아늑한 시뮬은 좁은 장르 — 짧은 영상으로 보여 줄 장면(나르기·깨달음·개미 떼)과 지구 카드 공유로 대응.
- 수익 모델 보류.

### Scope Risks (PR-SCOPE: OPTIMISTIC → 조정 반영)
- 병목은 코드가 아니라 사용자의 폰 검수 루프 (여정 단계마다, 병렬 불가).
- 출시 필수 일(스토어·개인정보·등급·서명·Play 비공개 테스트 12명 14일·알림·폰 성능)을 MVP에 명시.
- 분가는 사용자 결정으로 첫 출시에 확정 — 화면 밖 마을 요약 계산(B11)과 폰 성능이 선행 조건.

### Open Questions
- 꽃 가림 처리 방식 (아트 바이블).
- 성능 예산 실측값 (ADR).
- 친구의 선반(온라인) 기술 방식 — 첫 출시 뒤.
- 수익 모델.

## MVP Definition (첫 출시, 목표 4~5개월)

**반드시 넣기**
1. 병 하나: 창조 오프닝 → 스타터킷 → 이름 → 첫날(거인의 수첩) → 깨달음·제단·공물 → **첫 빵(튜토리얼 끝)**
2. 정착민 경제: 빵 사슬 + 손에 든 물건 + 더미·멈춤 표시 + 나르기·길 자라기 (경제 지도·촌장 판단은 뒤로)
3. 사건 연출 E1-0~6 (+ E1-7은 첫 완공·이주민·위기만), 처음 겪는 사건 안내 창, 도구가 사건과 함께 열림
4. 마을의 삶: 하루의 흐름, 대화, 연애(설렘~혼례), 마을의 날 하나(추수 축제), 아이 놀이 2종, 다툼·화해 1종, 아기 돌봄·유모차
5. 소원 = 실제 손짓, 계시 = 가르침 고르기, 탄생의 축복
6. 위기: 곰팡이·떠돌이 물방울·**개미 군단**, 애벌레 사냥, 거대 과일
7. 안개를 주민이 걷음 + 큰 나무 다섯 + **분가 마을 하나** (사용자 확정) — 화면 밖 요약 계산 포함
8. 시대: 개척기 → 마을, 비운 시간·돌아온 편지·알림, 저장
9. **출시 트랙**: 폰 성능 실측·예산, 스토어 자료·개인정보·등급·서명(AAB), Play 비공개 테스트(여정 3단계 끝 무렵 시작, 14일+), 로컬 알림

### Scope Tiers (if budget/time shrinks)
| 단계 | 내용 |
|---|---|
| **전체 꿈 (1~2년)** | + 친구의 선반(온라인 이웃·다리·이주민 선물), 여러 병·기후, 읍내~영지 시대, 마을 사이 교역, 계절 운영 |
